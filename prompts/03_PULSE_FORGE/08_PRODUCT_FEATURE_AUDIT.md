# Product Feature Audit

> Operating contract: [00_CORE/MASTER_DAW_HARDENING_PROMPT.md](../00_CORE/MASTER_DAW_HARDENING_PROMPT.md) — Purpose, 8-step operating loop, non-negotiable rules, required output.
> Materialize a standalone copy: `npm run prompts:build -- 03_PULSE_FORGE/08_PRODUCT_FEATURE_AUDIT.md`

## Product-specific mission

Audit the KYX features that are **distinguishing product bets**, not table stakes.
Phases 1–6 and 8–10 of the orchestrator already cover generic DAW reliability
(critical path, persistence, undo, contracts, audio engine, performance,
security). This phase covers only the code that exists because this product
makes a specific promise that a generic DAW would not.

Do **not** re-audit the transport, the command system, the audio graph, or the
persistence layer for generic correctness — that is phase 5 and 6. Audit them
here only where a product-specific feature sits on top of them and can misuse
them.

### Scope 1 — Text-to-beat intent pipeline

`src/intent/pipeline.ts`, `src/intent/providers/{local,symbolic,candidate}.ts`,
`src/intent/plan.ts`, `src/intent/normalize.ts`, `src/intent/text-parser.ts`.

The product promise: a user types a sentence and gets a deterministic,
reproducible musical plan.

Stress:
- ambiguous phrasing, typos, mixed languages, empty or whitespace-only input
- contradictory constraints in one sentence ("dark but bright", "120 bpm at 128")
- adversarial or over-long input; the `intent.text` cap is 300 characters
- the same intent re-entered after unrelated project edits
- a provider failing, timing out, or returning a malformed plan

Look for:
- nondeterminism — the same seed + intent must yield the same plan (AGENTS.md §3.4)
- a failure path that throws into the UI instead of falling back
- parse results that disagree with what the user literally typed
- normalization that silently mutates user meaning
- the intent hash changing for a cosmetic reword in a way that breaks dedup

### Scope 2 — Generative track runtime

`src/generative/{runtime,registry,capture,conditioning,validation,resample,
latency,timeout}.ts`.

The product promise: a provider generates audio, it is captured, playable, and
resamplable.

Stress:
- provider returns nothing, partial audio, or audio longer than the bar budget
- capture interrupted by a transport change, project switch, or tab suspend
- the same track regenerated twice — does it duplicate or replace?
- resample of an already-resampled buffer
- a project saved mid-generation and reopened

Look for:
- an unbounded audio queue or capture buffer (memory leak per generation)
- a provider that is awaited on the UI thread
- timeouts or circuit breakers that are absent, or that never trip
- generated audio that bypasses the undo/redo command path
- provider failure leaving the track in a half-initialized state

### Scope 3 — Collaboration and Y.Doc bridge

`src/collab/{CollabSession,CollaborationProvider,YDocStore,transportSync,
jamRoles}.ts`, `src/commands/yDocBridge.ts`.

The product promise: two people can edit one project without corrupting it.

Stress:
- a peer that disconnects mid-transaction
- concurrent edits to the same track, pattern, or automation lane
- a slow peer replaying a large backlog against a newer local state
- local offline edits followed by a reconnect
- project switch while a session is live
- the same command applied from both the local command path and the Y.Doc path

Look for:
- state that is authoritative in one path and merely mirrored in the other
- an undo that cannot express a remote change
- `applyToYDoc` and `execute` disagreeing for the same command
- a relay URL that is not validated through `isAllowedServerUrl`
- reconnect logic that clobbers newer local work

### Scope 4 — Portable pack and share codes

`src/export/{packCode,shareCode,kitCode,themeCode,bindsCode,zip}.ts`.

The product promise: a project or a kit can leave the app as a link and re-enter
intact.

Stress:
- a code generated by an older build replayed into a newer one
- a truncated, hand-edited, or bit-flipped code
- a payload at the documented caps (share tokens 2 M chars / 8 M decompressed;
  project JSON 10 MB; audio samples 25 MB)
- a decompression bomb at the boundary
- a filename or project name containing quotes, newlines, or RTL characters

Look for:
- missing or bypassed sanitizers on any field that reaches the DOM or disk
- a decode path that trusts the decoded shape
- caps that are checked after allocation rather than before
- round-trip loss: encode then decode must reproduce the source exactly

### Scope 5 — Groove and artist-profile data

`src/ai/grooves/*.ts`, `src/intent/{artists,artist-mix,semantic,
artist-profiles}/`, `src/project-model/{templates,template-pack2}.ts`.

The product promise: musical data ships in the build and is editable, and the
same seed reproduces the same groove.

Stress:
- a profile added to the registry but not to every consumer map that is
  `Record<Genre, …>` — the exact class of defect that surfaces as
  `Property '<newGenre>' is missing`
- a template that opens into a project failing `validateProjectShape`
- a groove whose parameters produce silence, clipping, or an empty pattern
- editing a data file in place and finding the old value still cached

Look for:
- a union type widened without updating every exhaustive map or switch
- a constant that the docs cite but the data no longer contains
- generated or vendored data that has drifted from its source

### Scope 6 — Route-level apps and the desktop shell

`src/landing/`, `src/gallery/`, `src/embed/`, `src/embed/main.tsx`,
`desktop/main.cjs`, `desktop/preload.cjs`.

The product promise: the public pages and the installed app are safe to ship.

Stress:
- a shared component used by both the main app and an embed, where the embed
  lacks a capability the app assumes
- the embed rendering untrusted query or route data
- the gallery rendering a hostile submission
- the desktop shell under an auto-update that arrives mid-session
- `preload.cjs` exposing more context bridge than the renderer needs

Look for:
- `innerHTML`, `dangerouslySetInnerHTML`, `eval`, or `new Function` anywhere
  under `src/` (AGENTS.md §3.10 — a regression here is a security regression)
- a preload surface wider than the documented contract
- embed/gallery code paths that reach the main app's project store
- an update path that can leave an unpacked build half-written

### Cross-cutting requirements for this phase

- A product feature is only safe if its **failure mode is defined**. For each
  scope above, state what the user sees when the underlying provider, peer,
  network, or file system fails.
- Prefer proving a defect over reading for one. Reproduce it in a test before
  changing code whenever practical, per the operating contract.
- If a scope is genuinely healthy, verify it and report that. Do not
  manufacture findings to justify the phase.
- Keep changes local. A defect in the generative runtime is not a licence to
  redesign the intent pipeline.
