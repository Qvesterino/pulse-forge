ui(material): one bevel recipe for the shell's control family

The plan's reason for this wave was wrong and is corrected in the same commit:
it said "today KYX has flat surfaces with thin borders". Measured, the bevel
already exists on ~217 surfaces. What is missing is ONE recipe — the top
highlight lands at twelve different strengths, and two controls sitting next
to each other in the same toolbar can disagree.

Measured before (scripts/material-audit.mjs, 1440x900):

  .btn / .btn-small   rgba(255,255,255,0.075) inset 0 1px 0  + rgba(0,0,0,0.18) 0 1px 2px
  .row-pad            rgba(255,255,255,0.08)  inset 0 1px 0  + amber inset 0 -2px 0
  .track-header-name  rgba(255,255,255,0.11)  inset 0 1px 0  + amber inset 2px 0 0
  .pattern-chip       rgba(255,255,255,0.2)   inset 0 1px 0  + amber glow
  .track-tab          rgba(255,255,255,0.32)  inset 0 1px 0  + dark inset 0 -1px 0
  .dock-tab           none
  .preset-chip        none

Two of the busiest surfaces had no shadow at all: the dock tab row is the
primary navigation of the bottom half of the studio and was flat, and the
baseline 0.075 does not read as an edge on this background at all.

Adds two tokens and applies one recipe to the baseline family:

  --bevel-hi  1px inset white on the top edge
  --bevel-lo  1px inset dark on the bottom edge

.btn 0.075 -> 0.10, .btn-small -> 0.10, .dock-tab none -> 0.10, .preset-chip
none -> 0.10. The bottom inset is new everywhere it is applied (only .track-tab
had one) and is the half of the effect that reads as lifted rather than tinted.
The 0.075 population (67 surfaces) is gone from the census.

Deliberately not touched: .track-tab (0.32), .row-pad (0.08),
.track-header-name (0.11) and .pattern-chip (0.2). Their highlight is a
SELECTION signal — each carries an amber inset alongside it — and normalising
them to the baseline would flatten "this channel is selected" into "this is a
button". The census samples the first matching element of a selector, so their
values are state samples; rewriting them from one sample is how this project
arrived here. Also untouched: 122 piano-roll keys (2 on screen), 268
catalogue rows, 256 step cells — bevel on texture is noise, and box-shadow on
hundreds of elements is paint cost.

.preset-chip is in the family for a checked reason, not a loose one: grep of
07-project-browser.css shows .preset-chip.active changes background, border and
colour and nothing else, so there is no competing state recipe to break.

scripts/material-audit.mjs becomes a gate: each declared role must resolve to
the token's alpha, exit 0/1/2. Same reasoning as typography-audit — a census
histogram cannot see a rule that lost the cascade, and this layer sits before
26-settings-glass.css, which is allowed to restyle controls. Falsified by
setting --bevel-hi to 0.14: all four roles went red with the computed value
named.

Also fixes a regression this session introduced. Wave 3 raised the channel name
from 12px to 13px so it would match the track header, and at 13px the label
column no longer fits the longer factory names: "Kick Techno" renders as
"Kick Tech…". Rather than give the pixels back and reintroduce two sizes for
one role, the full name goes in a tooltip — truncated-with-tooltip is how FL
Studio handles a narrow channel label. CSS truncation never touches the
accessibility tree, so the button's accessible name was never affected.
