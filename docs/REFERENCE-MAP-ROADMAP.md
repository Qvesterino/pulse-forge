# Reference Map — implementačná roadmapa (audiokey-analyzer + beat_modifier → KYX)

> **Cieľ:** KYX vie vziať referenčný audio súbor a vytvoriť z neho **mapu „kde čo je"**
> (BPM + beat grid, key + Camelot, energy krivka, štruktúrne sekcie, groove feel,
> orientačné drum/bass/chord náhľady) — a túto mapu vie použiť ako **abstraktný vstup**
> pre existujúci intent/generačný pipeline. **Nie beat-cloner.**
>
> **Zdroje (oba vlastné, licencie vysporiadané):**
>
> - `https://github.com/Qvesterino/audiokey-analyzer.git` — browser-native deterministický BPM/key analyzer (TS, nulové ťažké závislosti)
> - `D:\beat_modifier` — Python pipeline: analýza + extrakcia + Inspiration Spec + plánovač + symbolické generovanie (librosa/scipy)
>
> Status legendy: `[ ]` pending · `[~]` robí sa · `[x]` hotové · `[!]` potrebuje rozhodnutie.
> Čísla v `docs/CURRENT-STATE.md` sa menia **len** keď fáza reálne pridá instrument/efekt/šablónu/test-súbor — inak ho nesahej.

## Fáza 2 — „Kde čo je": energy + štruktúra + spektrálny kontext (port `analysis.py` bez librosy)

**Cieľ:** k BPM/key pribudne časová mapa skladby: energy krivka → sekcie (intro/build/drop/breakdown/outro/…) + loudness/spectral/stereo deskriptory + slovný sumár.

- [ ] **2.1 `src/reference/structure.ts`:**
  - [ ] `_energyCurve()` — port `_energy_curve/_rms_envelope`: Hann 2048/512, **16 bodov** (neskôr parametrické 16–64 podľa dĺžky), `energy = chunk-mean / max`, pozície normalizované 0–1.
  - [ ] `_structureFromEnergy()` — port prahov `0.4·median / 0.7` + merge + role `intro/outro/drop/breakdown/development` (mapovacia tabuľka rolí beat_modifier → KYX `Marker["type"]`: drop→`drop`, build→`buildup`, impact→`impact`, ostatné→`cue/custom`; `markerAssetFor()` sa tým pádom napojí zadarmo).
  - [ ] Rozšírenie nad zdroj: sekcie kotviť na **beat-grid z F1** (hranice snap na najbližší beat/downbeat-aproximáciu „každý 4. beat" ako `_downbeats()`), nie na surové bucket-hrany — inak markery plávajú mimo hudby.
  - [ ] Beaty/downbeaty: `beat_positions` z F1 + `downbeat_positions` aproximácia (explicitne označené ako aproximácia, nie detekcia — downbeat detektor je non-goal aj v audiokey).
- [ ] **2.2 `src/reference/descriptors.ts`:**
  - [ ] `_spectral()` — port zo `scipy.signal.spectrogram` na naše STFT (stredná polovica signálu, nperseg 2048/noverlap 1024): centroid, rolloff 85 %, flatness, low/mid/high energie, brightness. Čisto TS, žiadne scipy.
  - [ ] `_loudness()` — port 400 ms blokov (integrovaná LUFS-ish, peak dBFS, crest, dynamic range). Len deskriptor + varovanie pri clipovaní, **nie** mastering.

## Prílohy

### A. Odporúčané poradie (hodnota skoro, riziko neskoro)

```
F1 (jadro) → F4-lite (panel: drop + BPM/key + JSON)   ← prvý použiteľný míľnik
  → F2 (sekcie) → F4-full (markery + groove apply)
    → F3 (sketche) → F5 (inspiration + generovanie)
      → F6 priebežne s každou fázou
```

Dôvod: F1+F4-lite je samostatne užitočný „BPM/key analyzer v KYX" bez právnych aj technických rizík F3/F5. F3 bez F5 guardrailov do mainu **nepatrí**.

### B. Čo vedome NEPORTOVAŤ (a prečo)

- `beat_modifier` FastAPI/UI/CLI/jobs/storage → máme vlastné (commands, persistence, IndexedDB, `yDocBridge`).
- `librosa` runtime (`beat_track`, `pyin`, `chroma_cqt`, `onset_*`) → v browseri neexistuje; nahradzujú ho F1 DSP + `pitch-tracker.ts`. Recepty (pásma, prahy, vzorce) portujeme, binárky nie.
- `essentia / demucs` optional backendy → budúcnosť; registry-pattern (`BackendRegistry` s health/fallback, nikdy tichý cloud) prebrať až keď bude druhý backend reálne existovať.
- audiokey `components/ui/*`, TanStack, lovable-tooling → balast mimo náš dizajn a bundle.
- VST/AU hosting, nahrávanie vokálov, ASIO — mimo `VISION.md §1`, nepridávať infraštruktúru „keby".

### C. Invarianty, ktoré to celé drží (mapa na AGENTS.md / ARCHITECTURE.md)

1. Vrstvy: UI (zámer) → project model (pravda) → Transport (čas) → Scheduler (plán) → AudioEngine (výkon) → DSP (zvuk). Reference Map je **čítaný vstup**, nie piaty zdroj pravdy.
2. React nikdy nevlastní audio stav; mutácie len cez commands.
3. Rovnaký engine pre live aj offline — referenčné markery/groove musia znieť v exporte rovnako (F6 E2E).
4. Determinizmus + timeouty + fallbacky; AI/worker nikdy nehádže do UI/audio callbacku.
5. Custom realtime DSP do workletov; analýza do workerov (nie main thread, nie audio thread).
6. Schéma s `SCHEMA_VERSION` + migrácie; cudzie budúce verzie odmietnuť.
7. `useContext(ctx)` jediná cesta k AudioNodom (F1 decode cez engine context).
   8.–10. Žiadne VST/nahrávanie, žiadny WASM-DSP dnes, žiadne `innerHTML/eval/new Function`; user strings cez JSX/`sanitizeFilename`; `?server=` len cez `isAllowedServerUrl` (súvisí len ak by mapa niekedy cestovala linkom — dnes necestuje).
