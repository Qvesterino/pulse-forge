## 1. The one-paragraph competitive answer

> **No major DAW vendor ships an MCP server, and exactly one ships a first-party LLM agent.**
> Meanwhile the AI music tools that _are_ everywhere — Suno, Udio, Stable Audio, ElevenLabs,
> Google Flow Music — are **cloud generators that produce audio**, not systems that _edit a
> project you already have_. The gap is not "nobody has AI in a DAW". The gap is: **nobody has
> shipped an agent that can hear a project, propose a scoped and reversible change, prove what it
> changed, and hand the decision back to the user — inside a real DAW with a real audio engine.**
> KYX and ZYVO already own most of the _substrate_ for that. They do not yet own the perception,
> the shipped interaction, or the credibility.

### 6.2 What does NOT exist (verified absence over the pages reviewed)

- **No major DAW vendor ships an MCP server.** First-party pages for Ableton, Apple (Logic Pro),
  Steinberg (Cubase/Nuendo), Image-Line (FL Studio), Cockos (REAPER), Fender/PreSonus,
  Cakewalk-BandLab, Avid and Bitwig contain **no MCP server, no MCP SDK, no agent-control
  endpoint**.
- **Steinberg has not confirmed a Cubase MCP server.** A live thread on the official Steinberg forum,
  _"Any plans for a Cubase MCP Server?"_ (opened 2026-02-21, replies through 2026-09-10) contains
  **no staff answer**. _(Absence of evidence over the pages reviewed, not proof of absence.)_
- **FL Studio Gopher is the only major DAW with a first-party LLM agent confirmed.**
- **No open-source DAW ships an MCP server.** Ardour, LMMS, Mixxx, MuseScore and Zrythm expose
  scripting/plugin APIs, but no official MCP server was found (**U** — some API pages 404'd to the
  fetcher, so those scripting surfaces are only partially verified).
- **Verified automation surfaces an agent could target:** Ableton Extensions SDK, Bitwig user
  guide, Logic Pro Scripting Definitions, Mixxx wiki, LMMS, Ardour.

**The honest competitive read:** KYX and ZYVO already ship an **agent control surface that no
major DAW vendor ships**, and ZYVO already ships a **consent posture that only FL Studio Gopher
matches** — on the external transport. The in-app agent is deliberately more capable: in
`"command"` mode it may apply an allowlisted level/time change without a click, within a session
budget, and never while a Live Show is running (2026-10-26). That is a **product decision with a
guard**, not a safety net, and the guard's first run against a real show is still pending. What is
missing is not the surface — it is:

1. **Perceptual understanding** (KYX: none at all; ZYVO: objective DSP without measured accuracy);
2. **A shipped, human-approved, situated interaction** (no competitor has one either — but neither
   do we);
3. **Credibility** — no listening evaluation, no public proof, no third-party audit of the AI
   surface.

**That is the category-defining gap, and it is narrower and more achievable than "build an AI
DAW".** It is: _make the loop trustworthy, make it hear, and prove it._

## 8. Honest positioning (no autonomous-musical-excellence promises)

> **KYX and ZYVO are the DAWs where an AI agent is a first-class, permissioned, reversible
> participant in the project — not a chat panel, and not a generator you export from.**
>
> Every change an agent proposes is scoped, previewed, applied as one undoable transaction,
> verified against the audio, and recorded. Every capability still works with no model installed.
> We do not claim the agent makes better music than you. We claim you can **see exactly what it
> changed, hear exactly what it changed, and take it back in one keypress** — and that no other
> DAW lets you do that today, because no other DAW ships the loop.

**Three category-defining demonstrations to build** (each doubles as a product feature):

1. **The auditable proposal.** One request → a typed plan → an offline preview → a **numeric diff**
   (what changed, what was preserved, what could not be verified) → one transaction → a receipt.
   _The diff is the demo._
2. **The preserved groove.** "Tighten this, keep the feel" → a preview that is measurably tighter
   (median onset deviation ≤ 2 ms) **and** measurably still human (velocity correlation ≥ 0.99),
   with the preservation stated in numbers. _(K-2)_
3. **The impossible-for-them take comparison.** Two takes, a **numeric** diff (pitch, timing,
   loudness, spectral) and an instant switch — in a vocal DAW, on the performer's own audio, with
   no upload and no model. _(Z-1)_

## 9. Business viability for a small team

The competitive question is not only "can we ship it" — it is "can one maintainer afford it, and can
a user trust it with their work".

### 9.1 Running cost of the AI tier

| Cost line                           | Local-first (our plan)                                                                                          | Cloud-assisted                         | Commercial generators (Suno/Udio/Stable) |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------- | ---------------------------------------- |
| Inference                           | **~0** — CPU/CUDA on the user's machine                                                                         | per-minute API cost, scales with users | subscription; per-generation metering    |
| Model download                      | 1.07 GB (LFM GGUF) / 2.14 GB (ONNX) / 6.75 MB (ONNX intent)                                                     | none                                   | none (cloud)                             |
| Model licences                      | LFM v1.0 (<$10M revenue) · Whisper MIT/Apache-2.0 · ACE-Step MIT                                                | vendor terms                           | vendor terms                             |
| Hardware floor                      | **6–16 GB VRAM / 64 GB RAM** — the assumed tier                                                                 | none extra                             | none (cloud)                             |
| Failure cost of the tier going away | **low** — every capability has a deterministic fallback                                                         | **high** — bill and latency both move  | high                                     |
| Cost of the _legacy_ tier           | **0** — REAPER 7.75 and Bitwig 5.2.5 ship no AI at all, so a zero-AI tier is a legitimate market position today | —                                      | —                                        |

**The finding that matters for pricing:** the **AI tier is not the cost centre** — _support_ is. A
feature that works offline and deterministically generates a support ticket only when the user's
machine lacks WebGPU, or when a model pack fails its integrity check. A feature that requires a
cloud call generates a support ticket every time a network fails.

### 9.2 The five costs that are real

1. **Distribution.** The model pack is a separate download with a licence record and a digest. It
   must be an **explicit, opt-in, cancellable** download — never in the boot path (the web entry
   budget is 1,070 KB against a 2.14 GB ONNX bundle). Every pack needs a checksum, a licence file
   and a removal path.
2. **Model licences.** The LFM revenue cliff is the binding constraint; Essentia/aubio copyleft is
   the second; `Step-Audio-EditX` having no licence tag is the third. Licence review is a
   **release gate**, not a task.
3. **Maintenance.** Every model added is a permanent evaluation, licence, security and
   re-validation obligation — the LFM2.5 family moved 1.2B → 350M → 230M → 2.6B → 24B in six
   months, so "pin the version" means "re-run the suite on every base bump".
4. **Onboarding.** A 2.14 GB speech pack is a big first-run ask. The first-run experience must
   degrade gracefully: the product is complete with no model installed, and the download is
   offered _after_ the user has seen what it would do.
5. **Trust and support.** The AAW's promise is reversibility — so the support burden is dominated
   by **"the agent did something I didn't want"**. Every capability therefore needs an obvious
   undo, a readable receipt, and a cheap rejection. This is a support-cost decision, which is also
   why the attention budget is a product metric.

### 9.3 What this implies for pricing

- The **free tier should be the deterministic DAW** — full DAW, no model, no account. That is a
  viable market position today (REAPER, Bitwig), and it removes the trust problem for the majority
  of users.
- The **paid tier is the model pack plus the agent surface**, sold as _control_ (A/B, diffs,
  receipts, automation), not as _generation_. Generation is a commodity with vendors who have
  100× our training budget and a licensed catalogue.
- **No per-generation metering** in the local-first tier, and **no cloud dependency** for the core
  DAW — because the category's differentiator is trust, and trust does not survive a billing
  failure.
