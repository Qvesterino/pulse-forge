# AAW_SOURCE_LEDGER

**Status:** every source behind the frontier program's claims, with date, evidence grade, and revalidation date
**Compiled:** 2026-10-25 · **Research cutoff:** 2026-10-25
**Companions:** all other documents in `docs/frontier/aaw/`

**Grade key:** **A** official primary source (model card, official docs, official repo, licence text,
vendor product page / release notes) · **B** independent or community measurement with a stated
method · **C** secondary report without primary confirmation · **U** unverified.
**Method key:** 🔧 code inspection · 📄 document read · 🌐 web fetch · 🔬 measured locally.

**How to trace a claim end-to-end (the brief's claim ledger, spread across two files).**
Each numbered row below is the _source_ half of a claim. The other halves live beside it:

| Claim half               | Where it is                                                                                                                                    |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **Claim**                | the row's first column                                                                                                                         |
| **Source**               | this ledger, §1–§5, with the URL and the date observed                                                                                         |
| **Date**                 | "Date observed" column (all 2026-10-25 unless stated)                                                                                          |
| **Confidence**           | the **Grade** column (A/B/C/U)                                                                                                                 |

## 8. Method notes and honest limits

- **GitHub API budget.** The shared unauthenticated budget (60 req/h per IP, shared by every agent on
  this machine) was respected deliberately: ~14 requests in the model pass and ~24 in the competitive
  pass, with Hugging Face API + direct fetches used for discovery instead. No polling loop was run.
- **Search backend.** Where a first-party `web_search` was unavailable, discovery used the DuckDuckGo
  HTML endpoint; every consequential claim was then re-verified against the **primary** page.
- **No runtime verification — of the AI surface.** No build was run, no test suite executed, no dev
  server started, no model downloaded or executed, and **no listening evaluation was performed** in
  this program. Every "SHIPS" is a source-level claim.
  - **Update 2026-10-26, stated precisely.** The _research_ program above did no runtime verification.
    Since then, three implementation waves have landed and **were** verified by real test runs: the
    KYX MCP permission lattice (`D:\pulse-forge`, phase 2) and, in ZYVO (`D:\VocalForge_DAW`), the
    agent show lock (T0) and the in-app auto-apply wiring (T1) — the last one by 256 tests in 8
    affected suites plus the `check:invariants` gate. **What that does and does not cover:** it
    verifies the **agent control path** (consent, budget, show lock, apply-through-`AcceptProposal`).
    It verifies **nothing** about the audio side: no listening evaluation has been performed, no
    perceptual claim has been measured, and the "SHIPS" wording for the AI surface remains
    source-level. A green test suite about _who may change the project_ is not evidence about
    _whether the AI hears anything_.
- **Correction policy.** When a delegated finding was checked against the primary source and found
  wrong, the correction was stated explicitly in the affected document rather than silently edited —
  see `AAW_AUDIO_MODEL_LANDSCAPE.md` §1.6 for the worked example.
