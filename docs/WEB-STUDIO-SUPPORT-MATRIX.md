# KYX Web and Studio support matrix

**Status:** working qualification record, updated 2026-10-17

**Product scope:** [ADR 0014 — full-DAW scope](./adr/0014-full-daw-scope.md)  
**Execution plan:** [full-DAW roadmap](./ROADMAP-FULL-DAW.md)

This matrix separates implementation from software-path checks and physical
hardware qualification. “Implemented” does not mean certified for every host;
“software verified” does not prove device routing, analog latency or long-term
hardware stability. A hardware claim applies only to the exact host, OS, driver,
interface, channel map, sample rate and buffer recorded in its evidence.

## Status meanings

| Status                | Meaning                                                                                              |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| **Implemented**       | The product path exists; the cited boundary still applies.                                           |
| **Software verified** | Automated or repeatable software checks passed; no physical device claim is implied.                 |
| **Hardware smoke**    | A bounded stream opened on a named physical device; this is preliminary evidence, not qualification. |
| **Hardware verified** | A named physical configuration passed the procedure and has a retained test record.                  |
| **Not shipped**       | There is no user-available product implementation for this capability.                               |
| **Open**              | Evidence or a product decision is still required before a support claim can be made.                 |

## Composition and note editing

| Capability                                   | Status                | Evidence and boundary                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------------------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Long MIDI phrases and three-minute songs     | Software verified     | ADR 0047 and `docs/CURRENT-STATE.md`: 180-second save/reload/export and 181-second live soak passed; sparse MIDI notes exceed the bounded drum step grid.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Independent MIDI clips per instrument lane   | Implemented           | ADR 0044: clips are independently placed and scheduled on instrument lanes; Firefox live-audio, multi-peer collaboration and filtered-stem parity gates remain open.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Per-note velocity and fine pitch event lanes | Implemented           | Piano Roll Event Editor (schema v35); velocity is existing note data. A 12-semitone event changes rendered stereo RMS by >0.5% of baseline on all 24 built-in instrument runtimes. The latest Chromium and Firefox audits each passed 85/85 top-level note-expression checks, including the all-instrument fine-pitch sweep. Scheduler and service wiring tests verify expression reaches `AudioEngine.noteOn`; MIDI 1.0 output expression is not yet represented. WebKit on this Windows host exposes no Web Audio API, so Safari remains unverified.                                                                                                                                                                                                                     |
| Per-note pan                                 | Partially implemented | A shared capability map drives the lane list. Twenty-two built-in voice instruments declare per-note pan, including Drum Synth, Spectral Pad, Wavetable and Granular. Chromium and Firefox OfflineAudioContext checks cover centered baseline, hard-left/right isolation and simultaneous opposing-pan notes. Both latest browser audits passed 85/85 top-level checks. Ten selected live/offline parity cases include Wavetable and Granular with clean waveform nulls and deterministic repeats. TSAR and KOPA do not expose per-note pan; parity across every runtime and Safari remain open. |
| Per-note filter, release and Mod X/Y         | Partially implemented | Direct cutoff/resonance and Mod X/Y route to per-voice filters on 16 built-in instruments; release velocity is declared on 19. Chromium and Firefox each passed 85/85 top-level checks. Wavetable and Granular use their worklet voice path for both live and offline rendering; release-response ratios match at 3.37×/3.37× and 2.37×/2.37× respectively. Broader live/offline parity across all targets and runtimes remains open. WebKit has no Web Audio APIs in this environment, so Safari remains unverified. |
| FL-style slide note and portamento modes     | Partially implemented | Legacy `NoteEvent.slide` portamento routes through existing instrument glide paths. Separate no-retrigger slide notes bend held 808 and Acid 303 voices. Chromium and Firefox each passed 85/85 top-level checks, including source-to-target fundamental checks (55→110 Hz and 110→220 Hz) and live/offline parity for both held-slide cases. Graph tests prove no new oscillator is allocated and no held voice is a no-op. Other runtime support, Safari verification, note-color groups and external MIDI expression remain open. |

## Reference-device record still required

The owner-approved reference setup is not locked yet. For the first qualification
record, capture at least:

- exact Windows version/build and host PC;
- interface model, firmware and driver version;
- selected physical input/output connectors and their host channel numbers;
- sample rate, buffer/period and driver mode;
- KYX version/commit and whether the host is Web or packaged Electron;
- physical round-trip method and raw measurements;
- sustained-dropout, device-loss/reconnect, committed-audio recovery and
  save/reopen/export results.

Keep values blank until measured. Do not fill this record from OS defaults,
digital render-loopback estimates or listening impressions.
