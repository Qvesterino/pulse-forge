## P1-B — requestId idempotency ledger (`src/mcp/tools.ts`, 2026-10-13)

GAP-04: relative operations re-apply against live state, so a retried or
duplicated agent request double-applies ("−2 dB" twice = −4 dB) — the single
biggest blocker to unattended agent autonomy.

**Contract** (tests: `tests/mcp-idempotency.test.ts`, 10 specs):

- Every tool accepts an optional caller-supplied `requestId` (string, ≤128
  chars), injected into all 37 input schemas at module scope so the envelope
  is discoverable without hand-maintaining a mutating-tools list. The
  mirrors are regenerated (`npm run gen:mcp-mirrors`) and drift-gated.
- The ledger lives at the ONE chokepoint every transport shares
  (`executeMcpTool`); the dispatch body is unchanged (`executeMcpToolDispatch`).
- Only MUTATING outcomes are cached — reads always execute fresh, so a
  retried read never serves stale state.
- Failed calls (`isError` or not mutated) are not cached — fixing the args
  and retrying with the same id re-executes (agents can recover).
- Entries are scoped to the producing project document: the same id in
  another project executes fresh and re-binds there (a stale-project replay
  can never masquerade as the new project's state).
- A replay does not re-execute even if the change was undone since — the
  requestId names ONE logical operation, and the agent owns undo/redo. The
  replay returns the ORIGINAL outcome with `replayed: true` and a text
  prefix, so a retry can never be mistaken for a fresh execution.
- `kyx_batch`: a batch-level `requestId` caches the WHOLE batch outcome (its
  per-call read-backs included) as one unit — replay returns identical
  per-call results without executing any sub-call. Per-call requestIds
  inside `calls` also work (sub-calls dispatch through the same wrapper).
  This defines the partial-commit semantics: a replayed batch reports the
  same partial outcome it originally produced; it is not re-folded.
- The ledger is bounded at 256 entries (the undo stack's size) and evicts
  deterministically (FIFO, oldest first). Process-lifetime state with a
  `resetMcpIdempotencyLedger()` test hook.

**Why not `intentRouting.ts`:** the dedupe point belongs at the transport
boundary, where retries actually originate — one ledger covers every tool
(including the intent-routed `kyx_intent` path) instead of per-applier
plumbing. The appliers stay stateless.

## P1-A — document-derived target resolution (2026-10-13)

GAP-03: `"lower the vocal by 2 dB"` clarified with "which fader?" — the
deterministic layer was a closed vocabulary while the document is open.

**The applier split discovered during implementation** (sharper than the
roadmap's module list): exact gains and transposes execute through
`resolveProductionTargets`, mutes/pans/deletes through the strict
`resolveExactTargetTracks`, and fader asks through `trackIdsForTarget` —
three resolvers with different contracts. Vocal therefore lands where each
contract can serve it honestly:

- **Fader path owns vocal gains** (`src/intent/conversation.ts`):
  `FaderTarget` gains `"vocal"` (regex `vocals?|vox|vokal*|spev*|hlas*` with
  a volume-noun guard — `hlas(?!nej|it|ilo)` keeps "zníž hlasitosť basu" a
  bass ask and "hlasitejši" a loudness ask; the corpus caught the too-loose
  first cut). Resolution mirrors mix.ts MixTarget parity: a vocal-NAMED
  track (or vocalchop instrument) wins; otherwise the tracks carrying the
  singer's takes (audio-clip bindings); nothing when no take exists — never
  a positional guess.
- **Stated dB magnitudes are honoured** (`dBPercent`): "by 2 dB" / "o 3 db"
  converts to the fold's relative percent (×10^(−dB/20)). Before, a vocal
  dB-ask fell through to the vibe step (×0.82) — silently substituting the
  user's number (SILENT-DEFAULT rule).
- **Document-derived track names** (`parseNamedTrackFaderIntent` + route
  wiring): the user's OWN track names are addressable without a code change
  — "turn down the fx return bus", "stíš žiadny reed 200". Phrase-bounded
  deaccented matching against the live doc, resolved at ROUTE time so the
  ids the command executes on are the ids the router saw; wired BEFORE the
  loudness parser, which would otherwise claim "lower … by 2 db" as a master
  nudge. Same clamp, same fold, one undo step; `faderReadback` reports the
  document names.
- **Exact path (strict, destructive-safe)**: `ExactTarget`/`TARGET_RES`
  gain vocal for mute/solo/pan/remove/rename/duplicate;
  `resolveExactTargetTracks` matches name-or-kind ONLY (no clip-binding
  fallback for destructive ops); the production resolver gains a
  resolver-only vocal branch (named → clip-bound) so track selection works.
  `TARGET_PATTERNS` deliberately does NOT list vocal — production PARSING
  must never claim vocal asks, because vocal words are a deliberate
  creative-brief signal ("add vocals" still generates).
- **Melodic transpose declines vocal** (EN branch; the SK branch's inline
  noun list never matched): the op moves pattern notes and a vocal lane is
  audio takes — declining beats a silent no-op.

**Deliberately deferred:** the model target enum (`model-schema.ts`
`exactTarget`) — a grammar change would brick the v16 gated model until
retrain (same discipline as the fadeClip deferral); and the Ollama doc-context
half (`model-ollama.ts` discards `doc`) — the instruction template is
manifest-pinned and the model was trained without doc context, so injecting
it now shifts the input distribution for an already-deterministic win.
Both belong to the next corpus round + retrain + re-gate.

**Evidence:** `tests/intent-vocal-targets.test.ts` 17/17 (probe route +
execution parity + clip-binding semantics + named-wins + honest-null + live
names incl. diacritics + volume-noun guard + exact strictness + select +
brief protection); intent family 603/603 across 20 files; typecheck, drift,
prettier clean.

## P1-D — session isolation: UNKNOWN resolved + result-level attribution (2026-10-13)

**The UNKNOWN is resolved with evidence.** `server/mcp-core.mjs` + `server/
collab-server.mjs` (read in full at the audit revision): the web relay shares
the desktop's SINGLE-session model. `createMcpHub` held ONE `sessionConnected`
boolean and the collab server ONE `mcpRelaySocket` variable — every
authenticated `/mcp` caller (any MCP client, any agent, Bearer token) funneled
into that one socket → one KYX window → one document → one undo stack. A
second window connecting silently took over the relay (last-one-wins). GAP-06
applies to BOTH transports; there is no per-client session model anywhere.

**Remediation landed in two complementary layers:**

1. **Wire-level session ownership** (a concurrent session's in-flight work —
   `mcp-core.mjs` hub routes answers by session identity, the collab server
   takes ownership explicitly and closes the displaced window with a code the
   browser treats as final; `tests/mcp-relay-session-ownership.test.ts`
   pins it on real sockets). That layer closes the displaced-window defect:
   a replaced window can no longer resolve the live window's calls with
   answers about a DIFFERENT document. Not this session's commit — recorded
   here because it completes the same roadmap item.
2. **Result-level document attribution (this session's commit):** every
   mutating `executeMcpTool` result now states exactly which document it
   touched — a text line (`mutated on <surface> · document "<name>" (id
<id>)`, the one channel every transport forwards verbatim) plus
   structured `docId`/`docName` on `McpToolResult`. The surface label reuses
   the C6 attribution identities (`desktop-stdio` / `web-relay` / `qmr`).
   The line is appended exactly once per execution — a P1-B replay returns
   the ORIGINAL attributed result. Ownership routing makes a displaced
   window unable to answer; this makes each answer state its target.

**Evidence:** `tests/mcp-document-attribution.test.ts` 6/6 (mutation
attribution, surface naming, read-only cleanliness, replay-keeps-original-
identity, batch aggregate, post-rename name); MCP family 168/168 across the
9 committed suites.

**Still open (honest):** a project-lock for destructive ops (two agents
mutating one document still interleave — attribution makes it legible, not
safe) and true multi-session architecture (per-client documents) remain
future work, size L, per the roadmap's explicit "do not build before the
relay is understood" — it is understood now.

## P2-B — typed error contract (2026-10-13)

GAP-08: errors were free text — an agent had to substring-match to branch.

**The closed set** (`McpErrorCode` in `src/mcp/tools.ts`, eight codes, one per
distinct recovery action): `UNKNOWN_TOOL` (fix the call), `UNKNOWN_REQUEST`
(fix the op/action/genre within a tool), `INVALID_ARGUMENTS` (missing/malformed
args), `UNKNOWN_TARGET` (a named target resolves to nothing — pick one from a
read tool), `EXECUTION_FAILED` (the command itself failed; text carries the
reason), `PARTIAL_FAILURE` (a compound op stopped mid-form),
`UNAVAILABLE_ON_TRANSPORT` (the session lacks the capability), `POLICY_REFUSED`
(a gate declined — ask the user, do not retry blind).

**Mechanics:** every error result is constructed through one `mcpError(code,
text)` helper; all 65 pre-existing `isError: true` literals were converted,
plus 21 soft-decline sites that reported caller mistakes as NON-errors
("unknown track op", "no track with id", "no track matches family", "intent
failed", "cannot remove the last track" — a successful call that did nothing
was closer to fake success than to honesty; those are `isError` results now,
with their texts preserved). A source-text GATE in the test suite pins that
the raw `isError: true` literal appears exactly once (inside `mcpError`) —
a new error site that skips the helper fails the suite (the GAP-09 lesson:
coverage without a gate rots).

**Deliberately deferred:** mentioning the code set in `SERVER_INSTRUCTIONS`
(`server/mcp-core.mjs`) — that file is mid-edit by the parallel wire-ownership
wave; the legend ships in the next mirror-touching change.

**Evidence:** `tests/mcp-error-codes.test.ts` 11/11 — seven codes driven
through REAL dispatcher calls (no mocked handlers), the mid-form guard noted
honestly as not deterministically triggerable through public args, the
exhaustiveness gate, and the code-never-replaces-the-reason pin; MCP family
172/172 across 10 suites.

## P2-C + P2-D — batch safeguards, dry-run, parity ops (2026-10-14)

**P2-C atomic-or-explicit** (`kyx_batch`): defaults to the documented
partial-commit; `atomic: true` stops at the first failure and reports
`PARTIAL_FAILURE` with the executed/skipped ledger (executed calls stay
committed — a batch cannot un-execute its own prefix; the report is the
compensating-action honesty).

**P2-C dry-run envelope** (`dryRun: true` on every tool, schema-injected
beside requestId): the tool's full logic runs against a SANDBOX context —
validation, resolution and command construction are real; `ctx.execute`
advances a throwaway document chain, the live store never mutates and the
real dispatch never runs. The preview names the exact command labels that
would apply; invalid args fail identically; undo previews work; runtime/
export-side tools refuse (transport/export/gallery/audio-preview — a
dry-run cannot un-play a note); dry-run results are not idempotency-cached.
The gate lesson applied twice during the build: the exhaustiveness check
caught the atomic-batch error literals immediately (fixed via an
`mcpError` overrides parameter), and the first dry-run placement ran the
real dispatch BEFORE previewing — caught by the sandbox test and moved
ahead of it.

**P2-D parity ops**: `kyx_tracks duplicate` (the only capability where NL
exceeded MCP), `kyx_clips audioStretch` (rate 0.25..4; was UI-only),
`kyx_clips audioSlip` (offsetSec; was UI-only; take-locked clips refuse
through the command's own gate). Crossfade (two-clip targeting) and the two
NL gaps (scene-intensity, return-gain) remain RECORDED, not claimed.

**Evidence:** `tests/mcp-batch-dryrun.test.ts` 8/8 + `tests/mcp-p2d-ops.test.ts`
7/7; MCP family 188/188 across 12 suites; typecheck clean; drift green
(blessed serialization golden from the parallel wave; spec count 982).

## P3 — versioned action schema + readiness assessment + headless ADR (2026-10-14)

**P3-D versioned action schema (implemented):** `ACTION_SCHEMA_VERSION` +
`migrateModelAction()` in `src/intent/model-schema.ts`, wired into both
resolver validation paths (`model-resolver.ts`). Deliberately OUTSIDE
`toGbnfGrammar()` — the grammar pins the v16/INT8 training vocabulary; the
version travels at the envelope level beside the action. Unversioned
envelopes (every deployed model) migrate as v1; a FUTURE version refuses
with an update hint (project-model invariant #6 applied to model actions).

**GRAMMAR DRIFT — DISCOVERED, THEN RESOLVED SAME DAY (re-pin):** the pin
test proved the shipped model refused to load at HEAD — concurrent waves
grew MODEL VOCAB without re-pinning the manifest. The remedy decision was
made on evidence, not convenience:

- the artifact byte/hash pins were verified UNTOUCHED before the edit
  (model sha256 `0696787f…`, 1 803 717 bytes);
- a 50-head comparison of every trained softmax enum class against the TS
  validator found ZERO harmful mismatches — the only "missing" class,
  `abstain`, is handled decoder-side before validation
  (`INTENT_MODEL_ABSTAIN_MARGIN`); the TS side is a benign superset
  (`paramIntent`/`soundSwap`/`stepEdit` — kinds the model cannot emit);
- the ONNX decode path never consumes the grammar (it is passed only to
  GGUF-class runtimes — `model-worker.ts` step 3b);
- the ENTIRE post-pin grammar delta was verified additive: the
  `paramIntent` kind + `paramRole` enum (the parallel param-intent wave's
  committed grammar surface) plus the non-grammar P3-D block.
  `grammarSha256` was therefore surgically re-pinned (model/vocab pins
  untouched), the loader-level drift probe returns null — the model loads —
  and the cured classification was removed from `suite-expectations.json`
  (the ratchet requires cured reds removed). The NEXT corpus round should
  train the `paramIntent` head properly so the grammar and the model agree
  by construction, not by re-pin.

**P3-A unattended readiness (assessment; the harness itself is a product
decision):** the audit's prerequisites landed — safe retries (requestId
ledger), session ownership + attribution (parallel wave), typed error codes
(one per recovery action), atomic batches, dry-run pre-flight, the
capability map. What remains for TRUE unattended operation: a harness/loop
policy choosing retry-vs-ask per error code (the codes enable it; no
harness ships with the product), cooperative cancellation (relay timeouts
are best-effort — a cancelled call's window-side work still completes
unseen), and the destructive project-lock (P1-D residual). Each needs an
owner; none is blocked anymore.

**P3-H headless evaluation:** ADR 0046 PROPOSED (`docs/adr/0046-headless-
mcp-evaluation.md`) — recommends a test-only headless host over an in-memory
ProjectStore through the same `executeMcpTool`, owner-gated. Headless
remains zero-capability by design until the ADR is accepted.

**Evidence:** `tests/intent-action-schema-version.test.ts` 7 specs (G1 pin —
intentionally red as the owned signal; G2 envelope-leak guard; five
migration cases); `tests/suite-expectations.test.ts` 17/17 with the new
classification; MCP family green; typecheck clean.

## Changed files and rationale

### P0-B — `src/intent/exact.ts` · `parseExportIntent` widened (GAP-01, CRITICAL)

The noun is no longer limited to `project`: `mix|master|mastering|song|track`
(+ SK `projekt|skladba`) with determiners/fillers (`the|my|this|current|whole|
celý|…`) and prepositions (`as|in|ako|do|to|v`) now route to the master-bounce
export. Still **end-anchored**, so creative tails ("export a dark mix at 140
bpm") stay with their existing routes.

Deliberately **not** widened to `stems`: `tests/intent-e2e-audit.test.ts:1218`
encodes the existing contract that "export the stems" is NOT a master bounce
(stems are a different multi-file pipeline the intent route cannot drive).
That test stays green and the decision is now documented in the parser.

### P0-A — `src/intent/model-fallback-policy.ts` + `src/ui/IntentPanel.tsx` (GAP-01 safety net)

- `ACTION_VERB` gains the clip-editing verbs (`trim|fade|shorten|lengthen|
stretch|resize|split|slip|consolidate|quantize|reverse`).
- New exception **before** the structured-brief check: those verbs classify a
  route as NOT a creative brief even when the text-parser incidentally
  extracted a `length` field ("trim the clip at bar 5 to 2 bars" parses
  "2 bars" as a brief length — that number belongs to the edit). The
  documented precedence for "dark trap, remove hats" (structured brief wins
  over legacy edit verbs) is unchanged; composition-verb briefs win before
  both.
- The IntentPanel terminal route no longer falls through to `generate()` on a
  model miss. Only `isCreativeBriefRoute` generates; everything else lands in
  the clarify chip via `UNMATCHED_ROUTE_CLARIFY` (executable suggestions), and
  the miss is still mined (`outcome: "model-miss"` + `outcome: "clarify"`).

The regression table caught a REAL third instance of the fail-open class
during verification: "trim the clip at bar 5 to 2 bars" (no clips in doc →
falls through with a parsed length → generated). The policy exception above
is that fix, not a test accommodation.

### P0-C — `src/intent/arrangeWords.ts` + `src/intent/route.ts` (GAP-02, CRITICAL)

- New `ClipArrangeOp` member: `{ op: "fadeClip"; clipId; edge: "in"|"out";
seconds }`.
- `parseSelectedAudioClipFadeIntent`: resolves the selection against
  `arrangement.audioClips` ONLY (a scene-clip selection returns null — the
  pattern-clip arrange parser stays authoritative; pattern clips cannot be
  faded, and routing a fade through them would throw in `updateAudioClip`).
- Amount grammar: "over its/their final|last [N] bar(s)/takt" → fade-out of N
  bar-seconds at the clip's scene-pinned tempo (`audioClipDurationSec`);
  "first|prvý [N] bars" → fade-in; explicit "N s/sec/seconds/sek" and
  "N ms/milisek". **No length → null** (the request clarifies instead of
  guessing a fade); contradictory edge + bar phrase ("fade in … over its final
  bar") → null. Pre-clamped to the clip duration so the op reports the value
  that actually lands (the `audioClips.ts` clamp invariant holds through the
  bridge).
- Executed through `applyClipArrangeOps` → `updateAudioClip` → **one undoable
  command**; the fade branch resolves its clip against `audioClips` BEFORE the
  pattern-clip existence guard (which would otherwise read an audio id as
  "clip lost" and refuse).
- Route wiring: after `parseSelectedClipArrangeIntent`, reusing the `clips`
  kind — the existing direct-execute path (one command, status readback), not
  the pattern-clip preview flow (whose freshness checks are scene-clip
  shaped). A fade is milder than the deletes that path already executes.

**Not done, deliberately:** adding `fadeClip` to the MODEL clip vocabulary
(`model-schema.ts` `clipOp`). That changes `toGbnfGrammar()` → grammar-hash
drift → the just-gated v16 ONNX model refuses to load until retrained
(`model-worker.ts` drift pin). The deterministic bridge ships now; the model
vocabulary belongs to the next corpus round + retrain + re-gate.
