## Executive summary

No confirmed user-facing feature was found to be abandoned or unreachable in the candidate surfaces traced. Several apparent orphans are live: the sound/loop/preset browser is wired into the app, preset preview has both isolated and in-beat paths, the kit multiview and effect controls render inside the effect rack, and intent candidate feedback components are mounted in their owning panels.

The best recovery work is in three incomplete end-to-end contracts, not dormant code: qualify the existing “Bring a Song” route against real exports from the DAWs KYX names as targets; finish the machine-readable MCP result contract for the remaining 13 tools; and decide how much MIDI expression KYX should preserve when projects cross the Standard MIDI File boundary. Separately, reconcile stale inventory stamps and tool counts so the repository’s “single source of truth” is trustworthy.

This is a static audit. I did not run tests, builds, browser checks, or audio auditions. Existing verification artifacts are recorded below as repository evidence only.

## Top recoverable opportunities

Fewer than ten are listed because this audit found a small number of evidence-backed incomplete slices rather than a large inventory of dead features.

1. **Qualify “Bring a Song” with real exports (AF-01).** Export one representative short project from each named DAW using the published guide. Verify aligned audio, track names, MIDI tempo conversion, controller loss report, save/reopen, and render. Capture exact source-app version and export options.
2. **Close the MCP structured-output gap (AF-02).** Add machine-readable results to the remaining 13 tools, starting with workflows that chain catalog → target selection → edit → read-back. Keep structured results grounded in post-commit state.
3. **Choose a bounded MIDI expression interchange target (AF-03).** Start from supported FL/Cubase/Pro Tools exports and user loss-report feedback. Add only the next event types that have a deterministic mapping and test fixtures.
4. **Repair source-of-truth metadata (AF-04).** Reconcile `CURRENT-STATE.md`'s verification date and recent entries, then replace stale MCP counts in code/docs with a single source or a checked derivation.

## Five creative recombinations to consider

These are proposals assembled from existing KYX capabilities; they are not claims about shipped behavior.

1. **DAW Transfer Passport:** combine the existing transfer wizard, format loss disclosure, and source-specific guide into one preflight summary that says what will remain editable, what will be printed, and what will be lost before import.
2. **Round-trip Fixture Studio:** combine DAW-export fixtures with the existing save/reopen and offline-render acceptance path. A fixture could report audio alignment, MIDI timing, conversion loss, and render continuity as one portable compatibility record.
3. **Expression Translation Map:** connect Piano Roll event lanes to MIDI-file import/export mappings. Show which internal note controls have external equivalents for the selected instrument and include explicit loss/read-back checks.
4. **Typed Agent Recipes:** combine `kyx_catalog`, the canonical parameter registry, output schemas, post-commit read-back, and undo into a small set of tested multi-step recipes. This would make MCP feel like a reliable production surface instead of a bag of isolated tools.
5. **KYX sound-family kits:** combine sample mood/project-fit metadata, existing genre kits and kit-sketch sharing, and explicit Producer DNA A/B choices to help users find or build coherent families of kick, bass, texture, and transition sounds. Keep this as a small curated identity layer; the current browser/context ranking is already implemented.

## Do not revive

- **Do not treat VST3 factory enumeration, offline processing, or real-time hosting as abandoned code.** ADR 0035 deliberately ships only structural scanning in Wave 1; later waves wait on the native audio/render boundary and their own safety and release evidence. (`docs/adr/0035-vst3-hosting-policy.md:39-65`; `docs/ROADMAP-FULL-DAW.md:31-35`)
- **Do not add Rust/WASM DSP infrastructure as a cleanup.** ADR 0005 explicitly defers that path; the current realtime DSP boundary is AudioWorklet.
- **Do not revive legacy `fx`/`plugin` dock IDs as separate panels.** The current dock normalizes them to `devices` for compatibility; separate surfaces would restore a duplicate concept rather than recover a missing feature.
- **Do not call native project conversion “nearly implemented.”** FLP/CPR/PTX/AAF/OMF import, plug-in state, routing, and native layout are documented as unsupported. The supported handoff is aligned audio plus Standard MIDI with disclosed losses. (`docs/WEB-STUDIO-SUPPORT-MATRIX.md:73-74`; `docs/DAW-TRANSFER-EXPORT-GUIDE.md:3`)
- **Do not remove close-neighbor sounds from similarity scores alone.** The existing sound inventory flags a few close pairs for in-beat listening and explicitly treats redundancy as unconfirmed. (`docs/SOUND-LIBRARY-INVENTORY-2026-10-17.md:62-63`)
