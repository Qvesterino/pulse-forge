feat(fx): trim the Add Effect menu to fifteen daily devices

The select opened with 43 entries across 11 optgroups, which made choosing a
device a scroll rather than a glance. It now opens on fifteen, three per area:

  TONE      eq / msEq / multiband
  DYNAMICS  compressor / limiter / gate
  CHARACTER saturation / tapeSat / drumBuss
  MOVEMENT  haasWidener / chorus / tremolo
  SPACE     delay / reverb / duckDelay

Equal-height groups keep it reading as a grid. Mastering suites (ZENIT, APEX,
SPAN, TIDE, PRUD), specialty motion (stutter, comb, vowel) and spectral tools
(PORTAL, granularFreeze) keep their own MORE optgroups one layer down.

Nothing is removed: ADDITIONAL_EFFECT_GROUPS derives from
!DEVICE_MENU_EFFECTS, so all 57 remain discoverable exactly once, and
CORE + FLAGSHIP + MORE is what FxAddPopover and the mixer batch bar enumerate.
The zenit registry spec now asserts exactly-once across both layers rather
than pinning ZENIT to the first one - it is a mastering suite, so promoting or
demoting it is a product decision, not a registry invariant.

The gate now runs under vite-node so the DOM menu is compared against the live
EFFECT_META count instead of a literal that would rot like the ones it quotes
in zenit-composite.test.ts. Two of its own bugs are fixed in the same pass: a
non-anchored alternation (/^A|B|C\$/ vs /^(A|B|C)\$/) counted the MORE layer
as the first layer, and option[value] matches an empty value, so the \"+ FX\"
placeholder inflated the device total by one.

Gates: tests/effects-essential-kit.test.ts 24/24, zenit 8/8, typecheck clean,
drift:check clean, scripts/verify-essential-kit.mjs 18/18 in Chromium.
