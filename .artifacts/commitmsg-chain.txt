test(intent): deliverable 5 - the chain, past undo (NL -> audio -> save -> export)

The objective's headline deliverable is a demonstrated chain: natural
language -> structured intent -> validated command -> verified DSP/state ->
undo -> save/reload -> export. Every existing intent E2E spec (intent-e2e-audit
{,2,3}.test.ts, 141 specs) stops at `store.undo()`. Nothing in the repo drove
the last two hops from a request.

tests/intent-to-audio-chain.test.ts (3 specs) closes that gap with real modules
at every hop vitest can execute:

- routeIntentText, the function the IntentPanel actually calls, not the parser
  underneath it. It asserts kind: "clips" - the router hop IS the request.
- the fade value is checked against `audioClipsForPlayback`, the one choke point
  the scheduler, the live editor and renderProject share, plus
  computeRenderTicks / estimateRenderPcmBytes / resolveRenderTailSeconds and
  the export pre-flight. A document that says fadeOut: 0.5 proves nothing about
  audio; these are the renderer's own inputs.
- undo restores the document byte-for-byte, redo re-applies to identical render
  inputs, and normalizeProject round-trips to the same renderer view - the hop
  where D9-class losses live.

NOT VERIFIED, stated in the file header rather than glossed: the rendered PCM.
No vitest spec in this repo renders audio - renderProject needs a real
OfflineAudioContext and every caller in the test suite stubs it. Audible
verification belongs to `npm run test:browser`; claiming a rendered tail here
would be inventing a listening result.

Falsified hop by hop, not assumed:
- dropping the fade bridge in route.ts reproduces the exact pre-P0-C symptom
  the readiness report recorded (`expected 'pattern' to be 'clips'`),
- zeroing the fade in applyClipArrangeOps kills the command outright,
- zeroing fadeOut inside audioClipsForPlayback leaves the document carrying
  1.935 s while the renderer's view reads 0 - the spec catches precisely the
  "succeeded in the document, never reached audio" class.

The second spec is a control that proves the reload assertions can fail, so
the round-trip check is load-bearing rather than ceremonial.
