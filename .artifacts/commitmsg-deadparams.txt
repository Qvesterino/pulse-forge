fix(audit): the dead-parameter column was measuring the instrument, not the wiring

Asked to wire up the dead parameters from PLUGIN-AUDIT-2026-09-27 (28 effects,
72 parameters whose render is bit-identical at min and max). Measured them
first, and most of them are not dead.

scripts/probe-worklet-param-wiring.mjs renders the gate worklet in real
Chromium: same signal, two stimuli, three parameter-write styles. Seven of
the eight gate parameters the audit calls dead move the render by 0.5%..41% as
soon as the signal has gaps the gate can close. The registry applies them, the
worklet declares all eight, process() reads all eight.

THE CAUSE: the audit's test signal is a continuous sine+saw with one 250 ms
kick. After that it never falls below any threshold, so a gate never engages
and every threshold/range/hold/release parameter is correctly inert FOR THAT
SIGNAL. The harness already documents this exact trap for the vocoder
("every sidechain ducking knob is legitimately inert") and fixed it for the
sidechain input; it was never applied to the main sweep signal.

FIX: dynamics effects now sweep against a burst stimulus as well, best delta
wins, and ParamAudit.stimulus records WHICH stimulus produced it. Metrics are
untouched, and best-of-two can only turn a false negative into a true positive.

Measured after (KYX_AUDIT_ONLY=gate,compressor,limiter,duckDelay,transient):
  gate       7 dead -> 2   (attack, lookahead: timing-only, no metric sees it)
  compressor 1 -> 2        (scHpf + scBandHz are COMPANION-GATED by scMode,
                             whose default 0 keeps the band detector out of
                             the circuit entirely - correct by design)
  limiter    4 -> 4        (stimulus peaks -9 dBFS, below its threshold)
  duckDelay  2 -> 2        (needs a tail-length metric)
  transient  0 -> 0

The compressor count going UP is the proof the fix bites in both directions:
scBandHz was masked by the old stimulus and the new one exposed it.

Two hypotheses of mine were falsified on the way, and both are recorded in
docs/audits/.../DEAD-PARAMETERS-TRIAGE.md rather than quietly dropped:
- "setValueAtTime at currentTime=0 loses to descriptor defaults in an offline
  render" - false, direct .value assignment gave identical deltas;
- the first probe version was wrong twice: block-RMS dyn cannot see gate
  timing, and a 220 ms gap is too short for a 20 ms hold + 80 ms release, so a
  correctly-open gate read as inert.

Found, recorded, NOT repaired - a different cause, NOT VERIFIED either way:
beatMangler, reverseSwell, tapeStop and granularFreeze render identically to
dry in the isolated factory sweep (bypassDelta 0) while processing normally
in the host render (hostDelta 0.37..0.51). The sweep starts the transport
once and renders; the host advances it. A clock that never ticks, not a
signal that never engages.

No product code changed - nothing was broken, the instrument was.
